# Proposal: 运营者能远程要求更新、暂停线上功能

> State: in-progress · Updated: 2026-11-19

## Intent
线上功能上线后，服务端契约会变、可能出现安全问题、也可能遇到刷屏或恶意内容攻击。没有远程控制，旧版本的线上功能永远关不掉，出事时也只能把额度改成 0（用户看到的是「额度用完」，是错的）。这个机制只对带它的版本有效，所以必须在第一个线上版本 1.1 里就有。衡量：运营者不发新版本，就能让过旧的版本停用线上功能、暂停发布或新用户加入，并向用户说明原因。

## Scope
In scope:
- 最低支持版本：低于它的 App 停用线上功能（浏览世界地图、发布、举报、屏蔽），提示更新并能直接去 App Store；本地收藏、抠图、地图照常可用。
- 有新版本时的轻提示（不打断）。
- 运营开关：暂停发布、暂停新用户加入（第一次设置昵称）；被暂停时说明原因，而不是显示额度用完。
- 运营公告：一段可选的说明文字（中 / 日 / 英），在线上功能处显示。
- 服务端同样执行这些规则，绕过客户端也无效。
- 运营者在审核后台修改这些设置，修改有记录。
Out of scope:
- 锁死整个 App 的强制更新（本地功能不依赖服务器，没有必要）。
- 按地区开关线上功能（等「上架地区」的法规决定后另起变更）。
- 推送通知。

## Capabilities
- `online-availability` (new)

## Decisions
- 2026-11-18: 必须进 1.1 — 用户在讨论上线差距时同意先做这一项（「写提案并开始做」）。
- 2026-11-19: 版本过低只停用线上功能，不锁整个 App — 收藏完全在本地，锁死只会伤害用户。
- 2026-11-19: 读取配置失败时沿用上次的配置，没有任何记录时放行 — 服务端会再检查一次，客户端不必因为网络问题误伤用户。
