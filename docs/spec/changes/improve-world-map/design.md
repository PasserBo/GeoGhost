# Design: improve-world-map

## 1. 结构

```
Services/Explore/WorldFeed.swift        全世界最新的 200 件：App 启动时在后台加载，存在缓存目录里，下次启动先用
Domain/Explore/WorldPinLayout.swift     纯计算：哪些作品显示缩略图、哪些并进别人的缩略图成为数量、哪些是小圆点
Domain/Explore/WorldCamera.swift        纯计算：打开时框哪里；镜头移动用哪一档（平移 / 较长的移动 / 直接切）
Domain/Explore/OwnAreaPrompts.swift     纯计算：指向提示和邀请的出现条件；指向提示的关闭记录
Features/Map/WorldMapView.swift         世界地图本身：把上面几样接到地图、卡片条和提示上
Features/Map/WorldStrip.swift           卡片条、作品卡片、缩略图标记和小圆点
Features/Map/WorldPrompts.swift         顶部提示位、空白区域的面板（含邀请）、选一件公开
Features/Map/ArtMapView.swift           地图页：只负责「我的 / 世界」的切换和「我的」地图
```

出现条件、挑选规则、镜头决定都是不碰界面的纯函数，各有单元测试（`WorldMapTests.swift`）。

## 2. 作品从哪里来

- 一次不限范围的查询（`explore`，`cell_deg = 0`）返回最新的 200 件。不到 200 件就说明这是全部公开作品（`WorldFeed.isComplete`）。
- **全部作品都在手上时**（现在是 9 件）：地图上的标记、标记里有哪些作品、「只看这片区域」都直接从这份列表算，挪动地图不再发请求，也没有标记跳来跳去。
- **超过 200 件之后**：地图改用原来的按画面查询（`ExploreModel`，服务器按网格聚合），结果交给同一个挑选规则；点一个服务器聚合出来的标记时，再按那一格的范围查一次它里面的作品。格子的范围由 `floor(坐标 / 格子大小)` 算出，和服务器的分格方式一致（`20261112000000_online_phase1.sql` 的 `explore`）。这条路只有单元测试覆盖了挑选规则，界面上没有走过。
- 「最新发现」始终来自这 200 件。

## 3. 标记的挑选（`WorldPinLayout`）

按发布时间从新到旧过一遍：一件作品在屏幕上离某个已放下的缩略图不到 58 pt，就并进它（数量加一）；否则自己放一个。前 20 个是缩略图，之后的是小圆点。位置用地图自己的换算（`MapProxy.convert`），在镜头停下时和作品列表变化时重算。标记以「代表它的那件作品」为身份，缩放时同一件作品的标记不会重建。

世界地图只允许平移和缩放，不允许旋转，所以没有指南针。

## 4. 打开和加载

- `RootView` 在 App 进入前台、线上功能可用且版本不需要更新时调用 `WorldFeed.refreshIfNeeded()`。
- `WorldMapView` 创建时：有内容（新的或上次存下的）就直接以决定好的范围作为初始镜头；没有就用上次离开的镜头，或用户最近一次收藏的位置，然后最多等 3 秒，结果到了且用户没碰过地图再移过去。
- 「用户有没有碰过地图」的判断：自己发起的镜头移动先记一笔，镜头停下时有记录就销掉，没有记录就是用户动的。

## 5. 地图为卡片条留出固定的高度

卡片条在「有作品」和「空白区域」之间切换时高度会变。如果地图的可视范围跟着卡片条的高度变，内容一变、地图显示的范围就变，范围一变、内容又变，死循环（做的时候实际遇到了，界面卡死）。所以地图底部固定留出 136 pt，卡片条画在这块地方上面，它的各种状态都不能高过这个值——邀请因此做成了横向的紧凑排版。Apple 地图的标志在这块留白的上方，不会被挡住。另外，镜头回调收到和上次一样的范围时直接忽略。

## 6. 和提案不一样的地方

- **统计事件没有接。** 提案定了接三个事件，但 App 里现在没有任何上报使用行为的通道：`ui/event.yaml` 只是定义，现有的上报只有崩溃和错误报告，而且那份同意只涵盖诊断。接统计需要新的服务器接口、隐私政策和 App 隐私问卷的修改，是单独的一个变更。
- **提示里没有判断发布额度。** 额度要带着身份去服务器查，为一个提示去创建游客身份不合适。额度用完的说明仍然在发布页里。
- **指向提示只在全部公开作品都在手上时出现**（不到 200 件）。超过之后无法确定「那附近没有任何公开作品」。
- **没有判断诊断报告的询问弹窗是否正在显示。** 它是系统弹窗，盖在所有东西上面，而且只在拍摄结束后出现。

## 7. 没有验证的

- 真机上的流畅度，尤其是 20 个缩略图加小圆点的时候（模拟器里只有 9 件作品）。
- 离服务器远的用户的等待时间。
- 超过 200 件之后的那条路在界面上的表现。
- 指向提示在界面上的出现时机（条件有单元测试，样子有快照，没有在模拟器里等到它出现过）。
- 「较长的移动」这一档在 Apple 地图上的实际观感，以及八屏这个界线。
