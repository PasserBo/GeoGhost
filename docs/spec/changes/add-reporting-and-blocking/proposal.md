# Proposal: 举报不当内容、屏蔽用户，并在 24 小时内处理

> State: in-progress · Updated: 2026-11-12

## Intent
UGC 上架的硬性要求（审核指南 1.2），也是社区不被少数人毁掉的底线。任何人都能举报贴纸、屏蔽发布者；被多人举报的内容先自动隐藏；开发者 24 小时内处理每一条举报。

## Scope
In scope:
- 举报贴纸（选择原因，可附说明）；同一人对同一贴纸只算一次；举报后举报人立即看不到这张贴纸。
- 屏蔽发布者：立即看不到对方的所有贴纸；设置中可查看并解除屏蔽。
- 被不同用户举报达到门槛时暂时隐藏并重新进入审核（不是「未通过」），等待处理。
- 发布者在复审期间看到「复审中」（与首次的「审核中」区分）；审核不通过后看到「未通过」。
- 开发者收到新举报与待审核的通知，并有处理流程（通过 / 隐藏 / 封禁）。
- 被封禁的用户不能再发布，其公开内容对他人不可见。
Out of scope:
- App 内审核后台（先用 Supabase 控制台 + SQL）。
- 申诉流程（先通过支持页邮件）。
- 设备级封禁、设备断言（之后评估）。

## Capabilities
- `content-safety` (new)

## Decisions
- 2026-11-11: 举报每天 20 次；3 个不同举报人自动隐藏（09 §4–§6）。

- 2026-11-12: 举报原因：几个基本原因 + 「其他」（需填写说明）。
- 2026-11-12（agent 起草，待确认）: 具体原因与顺序：色情或暴力、仇恨或骚扰、暴露他人隐私（人脸、车牌、门牌等）、广告或垃圾内容、其他；说明最多 500 字。理由：覆盖审核指南 1.2 与街拍特有的隐私风险，又足够短，一屏选完。
- 2026-11-12（agent 起草，待确认）: 举报与屏蔽入口放在世界地图贴纸详情右上角的「更多」菜单；屏蔽需要确认，确认后详情关闭；举报和屏蔽都以访客身份进行，不要求先设置昵称。理由：与发布不同，举报不对外展示任何内容，不应增加门槛。
- 2026-11-12: 用户确认上面两条（原因列表与顺序、入口位置与访客身份），按草稿执行。
- 2026-11-12: 举报成功后，被举报的贴纸立即对举报人隐藏（之后也不再出现，开发者处理后也一样）；其他人不受影响，直到 3 人举报自动隐藏或开发者处理。理由（用户原话）：「我记得apple对于ugc有一个规定，需要举报后立刻能够隐藏被举报的ugc content。」
- 2026-11-12: 3 人举报后的自动隐藏改为「暂时隐藏并重新进入审核」：其他人看不到，发布者看到「审核中」（说明正在重新审核），审核台待审核和被举报两个队列都能看到并标为重新审核；通过则重新公开（不重复计入信任次数），拒绝则「未通过」。理由（用户原话）：「3人举报应该是暂时隐藏并进入再次审核状态」。
- 2026-11-12: 发布者那里把复审与首次审核区分开：显示「复审中」，说明因被多人举报、复审完成前其他人看不到（上一条中发布者看到「审核中」的部分由此取代）。服务器不加新状态：作者能读到自己帖子的 `published_at`，`pending` 且已发布过即复审。理由（用户原话）：「对发布者也应该显示复审」。
