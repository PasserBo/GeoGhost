## Purpose
运营者（开发者本人）在浏览器里看着图片审核新发布的贴纸、处理举报、封禁违规用户，并能确认没有超过 24 小时未处理的内容。

## ADDED Requirements

### Requirement: 只有运营者能打开
审核后台必须只对运营者开放；其他任何人打开都看不到任何帖子、图片或操作。

#### Scenario: 未登录打开
- **GIVEN** 访问者不是运营者
- **WHEN** 打开审核后台的任何页面或图片
- **THEN** 被要求登录，登录失败则看不到任何内容

### Requirement: 处理时限概览
后台首页必须显示待审核数量、待处理举报数量，以及其中等待最久的一条已经等了多久；超过 24 小时时必须醒目标出。

#### Scenario: 有超时的帖子
- **GIVEN** 有一张帖子已等待审核 26 小时
- **WHEN** 运营者打开后台
- **THEN** 首页显示它已等待 26 小时，并以警示样式标出

### Requirement: 待审核队列
待审核的帖子必须按等待时间从长到短排列，每条显示抠图、区域、发现日期、类型、发布者昵称，以及该发布者此前通过与未通过的次数和是否已被封禁。

#### Scenario: 打开待审核队列
- **GIVEN** 有 3 张待审核的帖子
- **WHEN** 运营者打开待审核队列
- **THEN** 最早提交的一张排在最前，每张都能看到抠图和发布者的历史

### Requirement: 被举报的帖子
有未处理举报的帖子必须单独列出，显示举报人数、各条举报的原因与说明，以及帖子当前的状态。因多人举报而暂时隐藏的帖子（见 content-safety › 多人举报后暂时隐藏并重新审核）必须同时出现在待审核队列中，并标为重新审核，等待时间从第一条未处理举报算起。

#### Scenario: 被多人举报
- **GIVEN** 一张帖子被 3 个人举报，已暂时隐藏
- **WHEN** 运营者打开被举报列表或待审核队列
- **THEN** 两处都能看到它并标为重新审核；被举报列表里显示 3 条举报的原因与说明

#### Scenario: 保留仍公开的被举报帖子
- **GIVEN** 一张只被 1 个人举报、仍然公开的帖子
- **WHEN** 运营者选择保留
- **THEN** 它仍然公开，并从被举报列表中消失

### Requirement: 审核操作
运营者必须能对一张帖子执行通过、拒绝或删除；通过后其他用户可见并关闭它的举报，拒绝后其他用户不可见，删除后帖子与图片都不再存在。

#### Scenario: 通过
- **GIVEN** 一张待审核的帖子
- **WHEN** 运营者点通过
- **THEN** 它从队列消失，其他用户在世界地图上可以看到它

#### Scenario: 删除
- **GIVEN** 一张被举报的帖子
- **WHEN** 运营者点删除并确认
- **THEN** 帖子和它的图片都被删除，发布者自己也只看到它不再公开

### Requirement: 封禁发布者
运营者必须能封禁和解除封禁一个发布者；被封禁者不能再发布，其所有帖子对其他用户不可见。

#### Scenario: 封禁
- **GIVEN** 一个发布了违规内容的用户
- **WHEN** 运营者封禁他
- **THEN** 他的所有帖子从其他用户的世界地图上消失，他再发布会被拒绝

### Requirement: 操作记录
每一次审核与封禁操作都必须被记录：何时、哪位运营者、对哪张帖子或哪个用户、做了什么；后台必须能看到最近的记录。

#### Scenario: 查看记录
- **GIVEN** 运营者刚通过了一张帖子
- **WHEN** 打开操作记录
- **THEN** 最上面一条是这次通过，带时间和运营者邮箱
