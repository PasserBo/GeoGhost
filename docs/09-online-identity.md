# GeoGhost — 线上身份与游客功能设计

> 状态：草案 · 2026-11-09 · 负责人：PasserBo
> 承接 [商业化与线上路线图](06-product-roadmap.md) 阶段 1–3；后端选型见 [技术架构](01-technical-architecture.md) ADR-007。

## 1. 原则

- **不注册也能完整参与。** 浏览、点赞、收藏、发布、举报都不需要注册。注册墙是线上功能最大的流失点，而 GeoGhost 的线上社区最缺的就是内容和人。
- **注册换来的是「不会丢」，不是「更多玩法」。** 注册（绑定 Apple 账号）的价值是换机找回、多设备登录；不用它来解锁功能或提高额度。
- **额度用来防刷，不用来逼注册。** 游客和注册用户的额度相同。真出现滥用时，先调低游客额度，而不是强制注册。
- **信任靠行为积累。** 新账号的前几张发布先审核，审核通过的次数越多越可信。注册本身不代表可信。
- **付费只看玩法深度。** 与 06 §2 一致：Pro / Pro+ 提高的是额度和深度，与是否注册无关；游客也能购买。

## 2. 身份的三种状态

用户只感知到「游客」和「已绑定」两种。技术上多一种「还没有会话」，用户看不到。

| 状态 | 何时进入 | 服务端有什么 | 用户看到 |
|---|---|---|---|
| **无会话** | 安装后从未使用线上功能 | 无 | 和 v1.0 完全一样，纯本地 |
| **游客**（匿名账号） | 第一次点赞、收藏、举报、屏蔽或发布时，静默创建 | 匿名用户 ID；设置昵称后才有公开资料 | 无任何注册步骤；发布前填昵称并同意社区规则 |
| **已绑定** | 用户主动绑定 Apple 账号 | 同一个用户 ID，增加 Apple 身份 | 设置页显示已绑定；换机后用 Apple 登录即可找回 |

- 浏览 Explore 和详情页**不创建会话**：公开内容对匿名角色只读开放（RLS 只放行已公开、未隐藏的帖子）。
- 绑定不改用户 ID，所以帖子、点赞、灵感夹、徽章全部原样保留，不需要数据迁移。
- 已绑定的用户不能解绑回游客；可以删除账号（见 §6）。

## 4. 次数上限

所有数字都是初始值，存在服务端配置表里，不发版就能调整。服务端按用户 ID 计数，客户端只负责显示剩余次数。

| 动作 | 免费（游客 = 已绑定） | Pro+ | 目的 |
|---|---|---|---|
| 发布 · 每月 | 20 张 | 不限 | 06 §5：控制刷屏，不是付费才能发 |
| 发布 · 每天 | 5 张 | 30 张 | 防脚本批量上传；Pro+ 也有上限 |
| 新账号先审 | 前 3 张进人工审核 | 同左 | 审核通过 3 张后改为直接公开、靠举报兜底 |
| 灵感夹 | 50 张 | 不限 + 分组 | 06 §5 |
| 点赞 · 每天 | 300 次 | 同左 | 只防刷，正常用户碰不到 |
| 举报 · 每天 | 20 次 | 同左 | 防恶意举报 |
| 改昵称 | 每 7 天 1 次 | 同左 | 防冒充、防反复换名骚扰 |
| 关注 · 总数（阶段 2） | 1000 | 同左 | 防刷关注 |

- **v1.x 不开内购时**，所有人都按「免费」一列执行。从第一天就有额度，以后开 Pro+ 只是放宽，不会出现「拿走已有功能」（与 06 阶段 0 的原则一致）。
- 到达上限时说明何时恢复（「本月还可发布 0 张，12 月 1 日重置」），不弹付费墙。付费入口只放在说明文字里的一行链接。
- 审核中的帖子自己可见，标「审核中」，目标 24 小时内处理（与举报处理时限相同）。

## 5. 什么时候提示绑定

绑定提示只在「用户有东西可能丢」时出现，可关闭，同一用户两次提示至少隔 14 天：

1. 第 3 张发布审核通过时：「你已经公开了 3 张，绑定 Apple 账号，换手机也不会丢。」
2. 灵感夹达到 10 张时。
3. 获得首位发现者徽章时（阶段 2）。
4. 设置页常驻一个「绑定 Apple 账号」入口。

不在启动、浏览 Explore、第一次发布时提示。

## 6. 防滥用与合规

- **上传走 Worker + App Attest。** 上传是成本最高的动作，Worker 在签发 R2 上传 URL 前校验 App Attest，只放行真机上的正版 App。点赞、举报等直接写 Supabase，用数据库层的限频挡住。
- **封禁。** 封禁用户 ID，同时用 DeviceCheck 给设备打上标记（每台设备 2 个比特，重装、换账号都还在），被标记的设备不能再创建游客发布。
- **举报自动隐藏。** 被不同用户举报达到阈值（初始 3 次）时先自动隐藏，再进人工队列。
- **合规清单。**
  - 审核指南 1.2：社区规则（EULA）、举报、屏蔽、24 小时内处理、联系方式。
  - 5.1.1：不强制注册。线上功能不需要账号，正好符合这一条。
  - 5.1.1(v)：提供删除账号。游客与已绑定用户都在 App 内一键删除全部线上数据。
  - 审核备注：说明审核员无需登录就能体验发布、举报、屏蔽。

## 7. 技术要点

- **会话存 Keychain**，不存 UserDefaults，这样卸载重装后游客身份还在。
- **游客换机：** 如果把凭证存进 iCloud 钥匙串同步，游客换机也能找回。风险是 Supabase 的 refresh token 一次性使用并会检测重复使用，两台设备共用同一个会话会互相踢下线，最后丢失身份。M1 要先验证可行做法，候选：每个游客另存一组随机生成、可同步的登录凭证，每台设备各自登录、各自持有会话。验证不通过的话，游客就只保证「同一台设备重装不丢」，换机找回只靠绑定。
- **购买与身份：** Pro+ 订阅用 StoreKit 的 `appAccountToken` 写入用户 ID，服务端校验交易后记录权益。游客也能购买；换机后「恢复购买」会关联到新设备上的身份。
- **默认私密不变：** 本地 `Artwork.visibility` 默认 `privateOnly`；发布是逐张的主动操作。

## 8. 与开发计划的对应

| 里程碑 | 内容 | 身份相关 |
|---|---|---|
| **M1 后端骨架** | Supabase 表（profiles / posts / likes / saves / reports / blocks / quotas）、RLS、R2 上传 Worker | 匿名会话、Keychain 存储、换机方案验证、配额表 |
| **M2 发布** | 选择公开 → 预览公开内容 → 首次设昵称与同意 EULA → HEIC 上传 → 审核中 / 已公开 → 撤回 | 发布额度、新账号先审 |
| **M3 Explore** | 视口查询、网格聚合、详情、点赞、灵感夹 | 无会话可浏览，首次互动静默建游客 |
| **M4 审核运营** | 举报队列、自动隐藏、封禁 + DeviceCheck、举报通知推给开发者 | 封禁按用户 ID + 设备 |
| **M5 合规上架** | 隐私政策、隐私标签、年龄分级、EULA、删除账号、审核备注 | |
| **M6 绑定 Apple 账号**（阶段 1.5） | Sign in with Apple、绑定匿名账号、换机登录、§5 的提示 | 进入阶段 2 前完成，因为关注和徽章让身份更值钱 |

阶段 1 上线时只有游客（M1–M5）；M6 紧接着做，可以单独发一个版本。

## 9. 待决

- 游客换机方案（§7）能否在 Supabase 上安全实现。
- 额度初始值（§4）上线后按实际数据调整，尤其每月 20 张是否太少。
- 新账号先审的张数（3 张），以及人工审核的处理时间能否稳定在 24 小时内。
- 是否允许已绑定用户再绑定其他登录方式（不做 Android 前只有 Apple）。
